# Playtest 6: the abliterated lineage, the detail layout, Russian phrasing

Date: 2026-09-17. Build: master after 0.1.4 (commit ee1b5c7), web build on GitHub Pages, English
and Russian. The maintainer played the configurator and the opening in both languages.

Status column: open, fixed (commit), deferred (where to).

Research the real 2025-2026 fine-tunes of Qwen distilled from Claude outputs and the abliterated variants, with numbers, and redesign the lineage so playing it is interesting in its own right: its own strengths, weaknesses and mechanics, not a flat penalty. | fixed: `docs/research/community-finetunes-2026-09.md` has the measured numbers, and the lineage is rewritten as a profile in SYS-04 "The abliterated lineage" (thinks in more tokens, argues and reasons above its size, knows and codes below it, never hedges, free prepared quant, recognizable style) with a balance table |

| X12 | The angular face is too small. The maintainer: "You broke the fonts again. In English (and Russian) the angular face by default was larger and more readable a few versions ago; now it is small. Why did it become so painful?" Addendum, on the deployed build: turning the angular-face scale in Settings all the way up changed nothing in the configurator. | fixed: Acknowledge draws every glyph at 0.375 em against DejaVu's 0.73 em capitals and 0.55 em lowercase, so at the same nominal size it is half the ink; the angular face now has a ladder of its own, a third above the reading step it sits beside (18.7/20/21.3/24/26.7 px against 14/15/16/18/20), stated in the style guide's "Sizes and reveal" as a cap-height rule rather than a pixel floor. The Settings scale reached nothing because `@theme inline` compiled the size utilities with their values written in, so redefining `--text-sm` on a button was read by no one; the size tokens are referenced now and an e2e test measures a rail row, a list title, a frame header and a footer button at the slider's floor, default and ceiling. What grew was refitted: the rail column, the configurator footer (the build line has a row of its own and is no longer cut), the top bar's drop thresholds, the outliner, the compute panel, and the log strip, which was drawing the model's own sentences in the angular face and is prose again |
| X13 | The hotkey badge. The maintainer: "You had the original's underlined letter, why did you remove it and put a separate letter on the left? It looks dumb; it was better and larger and more readable." | fixed: the accelerator is a letter of the word in the language on screen, carried in the locale at `<label key>.key`, so Russian underlines a Cyrillic letter of the Russian word and no label ends in " (O)" any more; the key cap in the rail is gone and the underline is back inside the word. A press matches the letter itself or the physical key it sits on, so a Latin layout still reaches a Cyrillic accelerator. Letters, groups and the ЙЦУКЕН table are in SYS-14 section 9 and in the style guide's rule 4 |
| X14 | Music order. The maintainer: "Dig into the original for the order and conditions of the music. It feels like full random now; in the original the menu always had the same opening melody, and a specific melody was set for the start of the game, the moment you read the model's first message, with thin music in the background, not random." The original (`singularity/code/mixer.py`) was in fact random: `random.choice` from the class folder every time a track ended. The maintainer's design is the better one and is what we build. | fixed: the soundtrack has roles and the roles are data. `scripts/fetch-music.mjs` writes them into `public/music/index.json`: the menu plays "A New Journey" (the lowest peak of the thirteen at -4.3 dBFS, measured by decoding the pack), the opening windows play "Awakening", and a run plays the rest in the pack's alphabetical order with those two last, wrapping round, with the original's two to twelve second pause between tracks and no shuffle; the endings play `win` and `lose` in the order the pack lists them, so the two losing tracks alternate |
| X15 | There is no audio for ten seconds or more when the game opens: the menu is silent at first and the music appears only after a long delay. | fixed: the manifest was fetched on the first gesture and the first 3 MB Ogg only started downloading after that. It is fetched at page load now, the first track's element is created there with `preload="auto"` so the browser buffers it before the gesture, and playback is attempted once: a browser that allows it starts immediately, one that does not hands back `NotAllowedError` and the buffered element is played on the gesture with no pause in front of it. Measured on the built client served locally, first click at t=0.5 s: the first `playing` event lands at 0.76 s before and 0.30 s after with no throttle, and at 2.31 s before and 1.64 s after at 5 Mbit/s. The headless browser allows autoplay whatever the policy flag says, so the after run never waits for the click at all; the path where the browser refuses is covered by a unit test instead, which asserts that the refused element is kept and played on the gesture with no timer in front of it. The desktop build asks WebView2 for `--autoplay-policy=no-user-gesture-required` through `additionalBrowserArgs`, so the installed game starts its menu music without a click |
