# SYS-14: Localization

Status: v0. English is the source language; every other language is additive and never blocks
content work. Planned target languages, in order: French, Spanish, Chinese, Arabic, Russian, German,
Japanese, Italian, Portuguese, Hindi.

## Rules

1. No user-visible string in code. UI strings live in `packages/ui/locales/en/*.json`; content strings
   in `packages/content/locales/en/<domain>.json`. Keys are stable, hierarchical, lowercase
   (`events.det_billing_anomaly.title`).
2. Format: ICU MessageFormat (plurals, select, number/date/currency formatting) through i18next +
   i18next-icu. No string concatenation in code; variables are named.
3. Runtime language switch without restart; fallback chain `xx-YY → xx → en`.
4. Extraction: `tools/i18n extract` scans UI code for `t("key")` and content for `*_key` fields and
   fails CI on unknown keys or unused keys. `tools/i18n status` prints coverage per language.
5. Translation workflow: JSON files per language; a Weblate project can be attached later; machine
   translation drafts are allowed only with a `"_machine": true` marker per file and must be reviewed
   before removal of the marker.
6. Fonts: a UI font with broad coverage (Noto Sans family subsets) plus the original's display fonts
   for titles where Latin-only is acceptable; CJK and Arabic fallbacks loaded on demand.
7. Text expansion: layouts must survive +40% length (German, Russian) and shrink for CJK.
8. Right-to-left: logical CSS properties everywhere; `dir` set from the locale.
9. Legacy: the original's `.po` files (de, fr, it, es, pt-BR, ru, sv, gd) are converted once for the
   strings that survive the rework, then retired; gettext is not used in the new client.

## Data with locale-dependent meaning

Country and city names come from content locale files (endonyms optional per language); currencies
and dates format per locale; numbers use ICU. The original's `numbers.dat` (fun numbers for base
names) stays as content with locale-independent digits.
